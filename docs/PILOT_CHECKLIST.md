# Pilot checklist — QuatHub

**Статус:** подготовка к пилоту (промпт 8). Не production-ready для открытого доступа.

## Перед пилотом с реальными пользователями

- [ ] Отключить или сменить все демо-пароли (`Demo1234!`)
- [ ] `AUTH_SECRET` и `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` — уникальные, не из `.env.example`
- [ ] Seed не запускать на пилотной БД с реальными данными
- [ ] HTTPS + стабильный домен
- [ ] Проверенный backup + restore drill (`docs/BACKUP_RESTORE.md`)
- [ ] Согласие 3–5 поставщиков / 2–3 подрядчиков на размещение прайсов и получение заявок
- [ ] Внешние curated-прайсы либо подтверждены владельцем, либо явно помечены как ориентир
- [ ] Rate limits активны (login / export / import / public links / sources)
- [ ] Админка только у platform_admin; список админов согласован
- [ ] Журнал ошибок без ПДн в клиенте; секреты не в логах

## Сценарии приёмки пилота

1. Гость: каталог товаров/услуг, вход с возвратом, выход
2. Buyer: организация → проект → кабель + публичная услуга в смету
3. Доставка + скидка → корректный итог → сохранение
4. Выпуск версии → PDF/XLSX/DOCX/CSV (клиентский) без закупочных цен
5. Две заявки тестовым поставщикам с кабинетом → ответ → принятие в новый черновик
6. Заявка внешней org без пользователей → `notificationStatus=skipped`
7. Публичная ссылка: открытие / отзыв
8. Нет доступа к чужой смете/экспорту
9. Новая цена после publish видна без ручной очистки кэша
10. Mobile ширина основных экранов

## Данные, которые нужно получить от поставщиков

- Юр. название, БИН, контакты ответственного
- Прайс (CSV/XLSX) или API: SKU, название, единица, цена, НДС, срок, наличие, регион
- Срок действия цен и условия пересмотра
- Согласие на отображение и на получение заявок через QuatHub
- Подтверждение, что цены не «для витрины» без обязательства отвечать

## Открытые продуктовые решения

- Модель оплаты и распределения средств при нескольких продавцах
- Нормативная смета РК (промпт 10) — отдельно
- Полный казахский UI
- Object storage вместо `.data/` для экспортов/импортов
- Реальная доставка уведомлений (email/SMS) вместо log-адаптера
