# QuatHub — Product Requirements Document (MVP)

**Продукт:** QuatHub / КуатХаб  
**Версия документа:** 0.1  
**Дата:** 2026-09-16  
**Статус:** подготовка (Промпт 0)

## 1. Цель продукта

Отраслевой B2B-портал для энергетики Казахстана: каталог товаров и услуг, проект с коммерческой сметой, экспорт документов и заявки поставщикам/подрядчикам.

**Главный сценарий MVP:**  
регион → поиск товаров/услуг → «Мой проект» → уточнение объёмов и цен → коммерческая смета → документы → заявки поставщикам.

## 2. Проблема и ценность

Сейчас расчёт закупки и монтажа часто собирается из разрозненных прайсов, Excel и переписки. QuatHub сводит оборудование, материалы, монтаж, доставку и пусконаладку в один расчёт с версиями, источниками цен и заявками без онлайн-оплаты.

## 3. Аудитория MVP

| Сегмент | Роль в продукте |
|---|---|
| Электромонтажные организации | заказчик/сметчик |
| Снабженцы и инженеры | заказчик/сметчик |
| Корпоративные заказчики | заказчик |
| Поставщики оборудования | поставщик |
| Подрядчики монтажа/испытаний | подрядчик |
| Частный заказчик | вторичный: шаблоны без жаргона |

Пилот: 3–5 поставщиков, 2–3 подрядчика, 10–20 реальных смет для проверки модели.

## 4. Вертикаль MVP

**Внутри:** электроснабжение и электромонтаж  
кабель; автоматика и защита; щиты; освещение; заземление/молниезащита; учёт ЭЭ; генераторы/ИБП; электромонтаж; проектирование; испытания/ПНР.

**Вне MVP, но в архитектуре:** подстанции, ВИЭ, накопители — через категории/параметры/шаблоны без пустых разделов меню.

**Следующие вертикали:** теплоснабжение, крупная генерация.

## 5. Роли и права

| Роль | Возможности |
|---|---|
| Гость | каталог, локальный черновик без ПДн |
| Заказчик/сметчик | проекты своей организации, сметы, версии, экспорт, заявки |
| Поставщик/подрядчик | компания, предложения, входящие заявки по своим строкам |
| Администратор | модерация, справочники, каталог, доступы, аудит |

Компания может совмещать покупателя и поставщика. Права — по членству и действию, не по одной роли в профиле.

## 6. Функциональные требования MVP

### 6.1 Каталог
- Товары и услуги с категориями, атрибутами, единицами, регионами.
- Фильтры по URL; пагинация и поиск на сервере (PostgreSQL).
- Карточка: характеристики, предложения поставщиков, НДС, наличие, срок, «В смету».
- «Цена по запросу» — текст + незаполненная строка в черновик.
- Сравнение предложений по сопоставимой единице и налоговой базе.

### 6.2 Проект и смета
- Ключевая сущность — **проект** (≥1 смета). Корзина = черновик сметы.
- Разделы, строки (каталог/предложение или ручные), начисления, скидки.
- Внутренний вид (затраты+продажа) и клиентский (только продажа).
- Жизненный цикл: черновик → неизменяемая версия → новый черновик.
- Optimistic concurrency; автосохранение; гостевой черновик → перенос при входе.
- Публичная ссылка на версию: opt-in, токен, срок, отзыв, noindex.

### 6.3 Расчёт
- Единый серверный модуль; клиентский итог не принимается.
- Коммерческая модель (не нормативная ПСД РК).
- Decimal; неизвестная цена = null + причина, не 0.
- Типы цены: от / фиксированная / диапазон / по запросу.
- Известный подытог vs полный итог при незаполненных строках.

### 6.4 Экспорт
- PDF, XLSX, DOCX, CSV из одного снимка версии и CalcResult.
- Клиентский и внутренний экспорт разделены.
- Черновик → предварительный снимок с маркировкой.

### 6.5 Заявки (без оплаты)
- Разбивка по поставщикам → выбор адресатов → создание заявок.
- Ответ поставщика = версия предложения; смета не переписывается.
- Принятие → новый черновик → новая версия.
- Изоляция: поставщик не видит чужие строки, конкурентов, перепродажу.

### 6.6 Админка и данные
- Справочники, модерация, аудит.
- Импорт CSV/XLSX прайсов с preview и транзакционным применением.
- Demo-данные явно помечены.

## 7. Границы MVP (не делаем)

- Нормативная ПСД / экспертиза / НДЦС как движок.
- Онлайн-оплата, эскроу, склад, тендеры, ERP.
- Инженерный расчёт безопасности (токи, сечения, уставки).
- Автосбор чужих каталогов.
- Заявленные партнёрства, лицензии, рыночные цены без источника.
- Российские нормативы/индексы как база для РК.

## 8. Нефункциональные требования

| Тема | Требование |
|---|---|
| Язык | RU основной; i18n готовность к KK |
| Валюта | KZT |
| Время | события UTC; UI — TZ проекта, default Asia/Almaty |
| Деньги | PostgreSQL Numeric + точная арифметика; Decimal в JSON строками |
| Доступ | серверная проверка на каждый объект; изоляция организаций |
| Аудит | значимые изменения каталога/прав/импорта |
| Документы | серверная генерация; шрифты RU/KK |

## 9. Критерии приёмки сквозного пути

1. Вход → проект в городе → кабель + монтаж → поставщик → доставка + скидка → корректный итог.  
2. Сохранение → выпуск версии → PDF/XLSX/DOCX/CSV с совпадающими итогами (±0,01 KZT).  
3. Две заявки двум поставщикам с изоляцией строк.  
4. Ответ поставщика → принятие в новый черновик; старая версия неизменна.  
5. Организация A не читает проекты B по прямому ID.

## 10. Допущения (зафиксированы)

См. также `ARCHITECTURE.md` и `IMPLEMENTATION_STATUS.md`.

1. Название QuatHub / КуатХаб — рабочее; ТЗ и домен не проверены.  
2. MVP = коммерческая смета по прайсам/расценкам, не нормативная.  
3. Платёж и доставка согласуются вне платформы; в UI это явно.  
4. Ставка НДС в seed/тестах — синтетическая, не заявление об актуальной ставке РК.  
5. Auth: Auth.js (NextAuth) + credentials/email magic link в dev; провайдер production — решение владельца.  
6. Хранение файлов экспорта: локальный диск в dev; S3-совместимое хранилище в staging/prod (адаптер).  
7. Email/SMS уведомлений в MVP — адаптер no-op / log; заявка в кабинете — реальная.  
8. Один активный draft на смету; версии immutable.  
9. Первые города пилота: Алматы, Астана, Шымкент (расширяемо).  
10. Монетизация вне MVP-кода.
